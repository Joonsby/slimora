# 슬라임 용병단 (가칭)

앱인토스에 낼 세로형 2D 방치형 RPG. 슬라임이 몬스터를 자동으로 사냥하고, 무엇을 사냥했느냐에 따라 진화한다.

## 현재 상태 — 첫 플레이 가능 프로토타입 (2026-10-28)

**자동 전투 → 처치 → 골드 · 흡수 → 강화 · 특성 · 진화 → 보스** 루프를 브라우저에서 플레이할 수 있다.
20장 200 스테이지 · 몬스터 30종 · 보스 20종 · 진화 3형태까지 들어 있다 (2026-10-30).

## 실행

Node 20 이상이 필요하다 (개발은 Node 24 에서 했다).

```bash
npm install              # client 의존성까지 설치된다
npm run dev              # http://localhost:5173
npm run dev -- --host    # 같은 와이파이의 휴대폰에서 접속할 때
```

앱은 `client/` 에 있다. 루트 `package.json` 은 명령을 `client` 로 넘기기만 하므로 `cd client` 후 실행해도 같다.

| 명령 | 하는 일 |
|---|---|
| `npm test` | 단위 테스트 (Vitest, 161개) |
| `npm run lint` | ESLint — 계층 간 의존 규칙도 여기서 검사한다 |
| `npm run typecheck` | TypeScript 검사 (앱 · 도구 두 설정) |
| `npm run build` | 타입 검사 후 `dist/` 로 빌드하고, 앱인토스 업로드용 `client/slimora.ait` 까지 만든다 |
| `npm run deploy` | `.ait` 를 앱인토스에 업로드 (먼저 `npx ait token add` 로 API 키 등록) |
| `npm run preview` | 빌드 결과를 띄워 본다 (http://localhost:4173) |
| `npm run sim` | 밸런스 시뮬레이터 — 화면 없이 실제 전투 엔진을 돌려 표로 출력 |
| `npm run store-assets` | 앱인토스 콘솔용 로고 · 썸네일 · 스크린샷을 `store-assets/` 에 생성 (먼저 `npm run build`, Chrome 필요) |
| `npm run android-icons` | 안드로이드 런처 아이콘 · 스플래시 PNG 를 `client/android/app/src/main/res/` 에 생성 (Chrome 필요) |

## 안드로이드 빌드 (원스토어)

같은 웹 빌드를 Capacitor 로 감싸 안드로이드 앱으로 만든다. 설정은 `client/capacitor.config.ts`, 네이티브 프로젝트는 `client/android/` 에 있다.
**Android Studio** 를 먼저 설치한다 (SDK 와 JDK 21 이 같이 들어온다).

```bash
npm run build:android    # 타입 검사 → dist/ 빌드 → client/android 로 복사 (.ait 는 만들지 않는다)
npm run open:android     # Android Studio 로 연다
```

Android Studio 에서 **Build > Generate Signed App Bundle / APK** 로 서명된 파일을 만든다.

- **키스토어(.jks)와 비밀번호를 잃어버리면 같은 앱으로 업데이트를 낼 수 없다.** 저장소 밖 두 곳 이상에 백업한다
- `appId`(`com.slimora.game`)는 원스토어 신규 앱 등록 때 입력하는 패키지명과 같아야 한다. 등록 후에는 바꿀 수 없다
- 앱 아이콘 · 스플래시는 `store-assets/src/android-icon.html` 에서 그린다. 고친 뒤 `client` 에서 `npm run android-icons` 로 `res/` 의 PNG 를 다시 만든다 (Chrome 필요)
- 원스토어가 APK 와 AAB 중 무엇을 받는지는 원스토어 개발자 콘솔에서 확인한다
- 업데이트를 낼 때마다 `client/android/app/build.gradle` 의 `versionCode` 를 올린다
- **원스토어 결제:** 원스토어 개발자센터에서 앱을 등록하고 **라이선스 키(공개 키)** 를 `client/android/app/src/main/res/values/strings.xml` 의 `onestore_license_key` 에 넣는다. 비어 있으면 상점이 「결제하지 못했어요」만 띄운다. 인앱 상품은 `shop.json` 의 sku 와 같은 ID 로 **관리형 상품** 으로 등록한다 (보석 · 스타터 팩은 지급 뒤 소비, 광고 패스는 확인만 해서 재설치 때 복원된다)
- 명령줄에서 gradle 을 돌릴 때 Android Studio 내장 JDK 가 21 보다 새것이면(`Unsupported class file major version`) `JAVA_HOME` 을 JDK 21 로 잡는다

## 조작

| 위치 | 기능 |
|---|---|
| HUD 스테이지 이름 | 사냥터 선택 시트 |
| HUD `도전 ▶` | 사냥 중일 때 다음 스테이지에 도전 |
| HUD `자동 ON/OFF` | 클리어하면 다음 스테이지로 자동 진행 |
| HUD `×1/×2/×3` | 전투 배속 (설정에 저장된다) |
| HUD `Lv` · 하단 `흡수` | 흡수 시트 — 슬라임 레벨, 계열별 흡수량과 특성 단계 |
| 하단 `강화` | 공격력 · 최대 HP · 치명타 확률. **길게 누르면 연속 구매** |
| 하단 `사냥터` | 클리어한 스테이지는 사냥, 바로 다음 스테이지는 도전 |
| 전투 로그 | 누르면 최근 30줄로 펼친다 |

## 이번에 구현한 것

| 항목 | 내용 |
|---|---|
| 프로젝트 | Vite 8 + React 19 + TypeScript 6 · Phaser 3.90 · Zustand 5 · Vitest 5 |
| 전투 엔진 | 순수 TS (`src/core/battle`). 행동을 예정 시각 순서로 처리해 프레임 속도와 무관하게 결과가 같다 |
| 몬스터 | 계열 3개 — 박쥐(빠름 · 흡혈) · 골렘(단단함 · 피해감소) · 화염(화상, 피해감소 무시). 2장마다 지역이 바뀌며 계열마다 새 몬스터가 나와 10개 지역 30종. 뒤 지역일수록 흡혈 · 피해감소 · 화상 확률이 조금씩 오르고, 4번째 지역부터 골렘이 강타를 쓴다 |
| 전투 규칙 | 자동 공격 · 치명타 5%(×1.5) · 처치 시 HP 10% 회복 · 사망 2초 후 재등장 또는 후퇴 |
| 스테이지 | 20장 × 10 = 200. 장마다 앞 6개는 박쥐 → 골렘 → 화염 순으로 한 계열씩, 7~9 는 섞여서, 10 은 보스. 처치 목표 10~25 (3스테이지마다 +5). 도전 / 사냥 / 실패 시 최고 클리어 스테이지로 후퇴 + 자동진행 OFF. 몬스터는 스테이지마다 ×1.2 |
| 보스 | 장마다 1마리, 20종. 골렘형(피해감소 · 강타) → 화염형(화상 · 격노) → 박쥐형(흡혈 · 격노) 순으로 돈다. 10장부터는 한 가지 효과가 더 붙는다. 제한시간 1장 45초 · 그 뒤 60초, 시간 초과도 실패 |
| 진화 | 흡혈 · 철갑 · 화염 슬라임. 한 계열 흡수 200 + 3 스테이지 클리어로 해금, 처음은 무료 · 해금한 형태로 돌아갈 때 골드. 숙련 5단계(그 계열 흡수량). 보스전 중에는 불가 |
| 성장 | 골드 강화 3종 — 공격력 +1.5 · 최대 HP +15 (비용 `floor(10 × 1.1^레벨)`), **25레벨마다 돌파 — 그 능력치 전체 ×3.5** · 치명타 확률 +0.5%p (비용 `floor(50 × 1.2^레벨)`, 최대 50레벨). 장 보스는 대개 돌파가 관문이다 (거대 골렘 25레벨 · 고대 화염룡 50레벨) |
| 배속 | ×1 / ×2 / ×3 정식 기능 (GAME_DESIGN D13) |
| 흡수 | 처치한 몬스터 계열을 흡수(처치당 `1 + floor((스테이지−1)/4)`). 계열별 특성 3단계(50 · 300 · 1,000) — 박쥐 흡혈 · 골렘 피해감소 · 화염 화상. 흡수 총합으로 슬라임 레벨(레벨당 기본 HP · 공격력 +2%). 슬라임이 가장 많이 흡수한 계열 색으로 물든다 |
| 테마 | 앱인토스 라이트 모드 기준 — UI 는 밝게, 전투 화면만 어두운 게임 아트 |
| 화면 | 세로 모바일 레이아웃 (360px 까지 확인). 전투 화면이 바탕을 채우고 HUD · 기록 · 도전 버튼을 그 위에 얹는다. 오른쪽 위는 토스 닫기 버튼 자리로 비운다. 캔버스는 기기 픽셀(최대 2배)로 그린다 |
| 아트 | 슬라임 · 몬스터 · 스테이지 배경 51종을 코드(SVG)로 그린다. 몬스터 그림은 그 스테이지에 나오는 것만 굽는다 (`client/src/art/`). 슬라임은 몸(흡수 색 tint) · 얼굴 · 형태 장식 층으로 나뉘고 눈을 깜빡인다. 장면마다 먼지 · 반딧불 · 불티 · 재가 떠다닌다. 글꼴은 Jua (Google Fonts, 못 받으면 시스템 글꼴) |
| 저장 | localStorage. 10초 간격 + 클리어/실패 즉시 + 화면을 떠날 때 즉시. 체크섬 + 직전 저장본 백업 |
| 오프라인 보상 | 1분 이상 떠났다 오면(앱을 다시 켜거나 화면으로 돌아오면) 그 사냥터를 실제 전투 엔진으로 2분 돌려 본 속도 × 떠난 시간(최대 8시간) × 50% 의 골드 · 흡수를 바로 준다. 복귀 창에서 보상형 광고를 보면 한 번 더 (2배) |
| 광고 | 앱인토스 보상형 광고 (`loadFullScreenAd` · `showFullScreenAd`, `userEarnedReward` 때만 지급). 빌드할 때 `VITE_AIT_REWARD_AD_ID` 에 콘솔의 광고 그룹 ID 를 넣어야 버튼이 나온다. 광고 중에는 효과음을 멈춘다. 개발 서버는 devtools 가짜 광고 |
| 효과음 | 음원 파일 없이 Web Audio 로 합성 — 타격 · 치명타 · 피격 · 처치 · 코인 · 레벨업 · 클리어 · 실패 · 보스 · 진화 · 구매. HUD 에서 켜고 끈다 (설정에 저장) |
| 용병 · 뽑기 | 보석으로 용병 8종(일반 4 · 희귀 3 · 전설 1)을 뽑는다. 1회 100 · 10회 900(희귀 이상 1명 보장), 확률 일반 70% · 희귀 25% · 전설 5%(등급 안에서는 같은 확률, 뽑기 화면에 공개). 같은 용병은 레벨업(최대 10, 넘치면 보석 20 반환). 2명까지 편성 — 슬라임 위를 떠다니며 지원 공격(슬라임 공격력 × 비율)을 하고 패시브(공격력 · HP · 골드 · 치명타 · 피해 감소)를 준다. 오프라인 보상 계산에도 들어간다 |
| 랭킹 | 토스 게임센터 리더보드 (토스 앱 안에서만). 점수 = 환생 횟수 × 100 + 모든 회차 최고 스테이지. 스테이지 클리어 · 환생 때, 이번 실행에서 올리지 않은 더 높은 점수만 제출. HUD 트로피 버튼으로 랭킹 화면을 연다. 미니앱 정보 승인 뒤에만 동작한다 |
| 보석 | 시작 선물 100, 모든 회차를 통틀어 처음 깬 스테이지마다 10 + (스테이지 − 1), 환생 50, 보상형 광고 50 (하루 5번), 상점 결제. 환생해도 남는다 |
| 상점 · 결제 | HUD 보석(+) · 용병 화면 「충전」으로 연다. 보석 300 / 1,100 / 3,800 (1,100 · 3,300 · 9,900원), 1회 한정 스타터 팩(보석 1,000 + 정수 5, 2,200원) · 광고 패스(5,500원). 상품 정의는 `client/src/data/shop.json`. 토스 앱은 앱인토스 인앱결제, 안드로이드 앱은 원스토어 인앱결제(SDK V21, `OneStoreBillingPlugin`), 일반 브라우저는 상점 없음. 지급하고 기기에 저장한 뒤에야 스토어에 완료를 알리고, 지급 전에 꺼진 주문은 다음 실행 때 지급한다. 같은 주문은 두 번 지급하지 않는다. 다른 기기의 서버 저장으로 바뀌어도 이 기기에서 결제한 것은 다시 얹는다. 화면 아래에 청약철회 안내. 저장 형식 v6 |
| 광고 패스 | 오프라인 보상 2배와 광고 보석을 광고 없이 바로 받는다 (광고 보석 하루 5번 제한은 같다). 영구 — 환생해도, 원스토어는 재설치해도 남는다 |
| 환생 | 1장 보스(스테이지 10)를 깨면 할 수 있다. 정수 = floor(3 × 1.19^(최고클리어 − 10)) (10 → 3, 50 → 3,265). 골드 · 강화 · 흡수 · 스테이지는 처음으로, 진화 형태 · 누적 기록 · 정수 강화는 남는다. 정수 강화 4종 — 공격력 · 최대 HP · 처치 골드는 레벨마다 ×1.1 (곱해서 쌓인다), 오프라인 보상 상한 +1시간(최대 4). 용병 패시브는 정수 강화 배율에 곱한다. 저장 형식 v4 |
| 튜토리얼 | 처음 몇 분 동안 환영 → 강화 → 도전 → 흡수 → 진화 → 환생 메뉴를 한 번씩 말풍선으로 짚는다. 짚은 메뉴를 누르거나 「알겠어요」로 넘어가고, 본 것은 설정에 저장 |
| 서버 저장 | 토스 앱 안에서만 [slimora-api](https://github.com/Joonsby/slimora-api) 에도 올린다 — 최대 30초 간격 + 화면을 떠날 때 즉시. 기기 저장으로 먼저 시작하고 뒤에서 맞추며, 두 쪽이 다르면 누적 획득 골드가 많은 쪽을 남긴다. 원스토어 앱 · 브라우저는 기기 저장만 |
| 테스트 | 전투 계산 · 진행 규칙 · 저장 · 세션 통합 · 밸런스 불변식 |

## 설정값 조정

밸런스는 `client/src/data/*.json` 만 고치면 된다. 코드는 건드리지 않는다.

| 파일 | 내용 |
|---|---|
| `balance.json` | 슬라임 기본값 · 상한 · 전투 상수 · 스테이지 스케일링 · `configVersion` |
| `monsters.json` | 몬스터 배율 · 공격 간격 · 효과 (`lifesteal` · `damageReduction` · `burnOnHit` · `heavyAttack` · `enrage`) |
| `chapters.json` | 장 20개 — 장 이름 · 일반 몬스터 3종(`pool`) · 보스 · 스테이지 10개의 이름과 배경. 출현 순서 · 처치 목표는 `src/data/chapters.ts` 가 펼친다 |
| `forms.json` | 진화 형태 — 요건 · 기본 보정 · 숙련 단계 효과 · 외형 |
| `legacy.json` | 정수 강화 (환생해도 남는 영구 강화) — 효과 종류 · 레벨당 수치 · 최대 레벨 · 정수 비용 |
| `mercenaries.json` | 용병 — 등급 · 외형 · 지원 공격(비율 · 간격) · 패시브. 뽑기 확률 · 보석 · 편성 수는 `balance.json` 의 gacha · gems · party |
| `upgrades.json` | 강화 종류 · 레벨당 증가량 · 비용 공식 · 돌파(`milestone`) |
| `families.json` | 계열 이름 · 색 (슬라임 물들기에도 쓰인다) |
| `traits.json` | 계열별 특성 단계 문턱과 효과 |

수치를 바꾸면 `configVersion` 을 올리고 `npm test` 와 `npm run sim` · `npm run sim:long` 으로 확인한다.
설정이 잘못되면 테스트가 실패하고, 앱은 화면에 설정 오류를 띄운다.

현재 수치(설정 0.8.0)로 자동 플레이(가장 싼 강화부터 즉시 구매)를 돌리면 ×1 배속에서 1 스테이지 약 1분, 1장 보스(10) 약 45분이다.
1 스테이지와 골렘이 처음 나오는 2 스테이지에서 몇 번 죽고, 4~7 스테이지에서 실패가 이어지다 25레벨 돌파로 보스를 넘는다.

`npm run sim:long` 은 진화 · 용병 뽑기 · 환생(새 스테이지를 1시간 못 깨면)까지 하는 자동 플레이어로 끝까지 간다 (×1 전투 시간, 오프라인 보상 없이).

| 스테이지 | 10 | 50 | 100 | 150 | 200 |
|---|---|---|---|---|---|
| 처음 깬 시각 | 45분 | 약 9시간 | 약 1일 | 약 2일 | 약 8~12일 (환생 30~40회) |

환생할 때마다 대략 한 장(보스 하나)씩 더 간다. 마지막 두 장(181~200)이 가장 오래 걸린다.
실제 플레이는 ×3 배속 · 오프라인 보상 · 결제가 있어 이보다 빠르다.

## 폴더 구조

```
client/src/
├─ core/          게임 규칙 (순수 TS). React · Phaser · Zustand · Date.now · Math.random 금지
├─ data/          설정 JSON + 검증기
├─ session/       GameSession — 엔진 구동 · 커맨드 적용 · 스테이지 전환 · 저장 시점
├─ store/         Zustand 스토어 (React 가 읽는 상태)
├─ persistence/   저장소 구현 (localStorage · 메모리 · 서버 저장 API)
├─ platform/      시계 · 화면 가시성 · 토스 로그인 코드 · 광고 · 랭킹 · 결제(앱인토스 · 원스토어) · 안드로이드 뒤로가기
├─ art/           슬라임 · 몬스터 · 배경 SVG 생성 + 흡수 색 계산 (전투 화면과 메뉴가 같이 쓴다)
├─ game/          Phaser 전투 장면 (계산 없이 그리기만)
├─ ui/            React 화면
├─ dev/           자동 플레이어 (밸런스 점검용)
├─ testing/       테스트 픽스처
└─ main.tsx       조립 지점
```

계층 간 import 규칙은 `eslint.config.js` 가 강제한다 (ARCHITECTURE 3장).

## 저장 데이터

브라우저 localStorage 의 `slime-merc:save` (현재본) · `slime-merc:save:prev` (직전 성공본).
처음부터 다시 하려면 개발자 도구 콘솔에서 아래를 실행하고 새로고침한다.

```js
['slime-merc:save', 'slime-merc:save:prev'].forEach((k) => localStorage.removeItem(k));
```

토스 앱 안에서는 같은 저장을 서버에도 둔다 (`client/src/session/cloudSync.ts`). 개발 서버에서 토스 없이 시험하려면
slimora-api 를 `DEV_AUTH=true` · `CORS_ORIGINS=http://localhost:5173` 으로 띄우고(기본 포트 3000), 그 서버를 가리키도록 `client/.env.development.local` 에 아래를 넣는다 (운영 빌드에는 들어가지 않는다).

```
VITE_SAVE_API_URL=http://localhost:3000
VITE_SAVE_DEV_USER=tester
```
