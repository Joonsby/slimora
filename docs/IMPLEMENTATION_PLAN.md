## 0. 원칙

- **화면보다 규칙을 먼저 만든다.** 전투 엔진을 테스트와 시뮬레이터로 굳힌 뒤에 Phaser 를 붙인다
- **단계마다 눈으로 확인할 수 있는 결과**를 낸다. 각 단계 끝에 확인을 받고 다음으로 간다
- 규모 표기: **S** 반나절~1일 · **M** 2~3일 · **L** 3~5일 (게임 개발 첫 경험 기준의 대략값)

## 2. 단계

### Phase 0 — 결정 확정 (사용자)

- GAME_DESIGN 2장 결정표를 검토해 권장안을 확정하거나 바꾼다

- **산출물**: GAME_DESIGN 결정표의 「권장」 → 「확정」 갱신

### Phase 1 — 프로젝트 골격 [S]

| 작업 | 내용 |
|---|---|
| 생성 | `client/` — Vite + React + TypeScript. Phaser 3 · Zustand · Vitest 설치 |
| 의존 규칙 | ESLint `no-restricted-imports` · `no-restricted-properties` (ARCHITECTURE 3장) |
| 타입 | `core/model/` 에 ARCHITECTURE 5장 타입 전부 |
| 설정 | `data/*.json` 초안 (GAME_DESIGN 5장 수치) + `validate.ts` + 테스트 |
| 레이아웃 | 세로 화면 골격: React HUD / 캔버스 자리 / 하단 메뉴. 안전 영역 여백 |
| Phaser | 빈 씬이 캔버스 자리에 뜨는지. React StrictMode 의 이중 마운트로 게임이 두 개 생기지 않게 |
| 측정 | 빌드 산출물 크기 기록 (Phaser 비중 확인) |

**완료 기준**: `npm test` 통과 (설정 검증) · 휴대폰 브라우저에서 레이아웃 확인 · 번들 크기 기록

### Phase 5 — 흡수 · 특성 · 진화 [L]

프로토타입 코드를 기준으로 **5A 흡수 → 5B 진화** 두 번에 나눈다. 흡수만으로도 「사냥한 계열에 따라 슬라임이 달라진다」의 첫 맛(색 · 특성)이 나오므로, 5A 에서 한 번 플레이로 확인한다.

#### 5A — 흡수 · 특성 · 슬라임 레벨 [M]

| 순서 | 대상 | 작업 |
|---|---|---|
| 1 | `data/` | `balance.stageScaling.absorbStep`(4) · `balance.level`(divisor 10 · 레벨당 +2%) · `monsters.absorbMul` · 새 `traits.json` (계열별 50/300/1,000 3단계). `validate.ts` 에 검사 추가 |
| 2 | `core/model` | `SlimeProgress.absorption: Record<FamilyId, number>` · `MonsterState.absorb` · `monsterKilled.absorb` · `grantBattleReward.absorb` |
| 3 | `core/progression` | `absorption.ts` (처치당 흡수량 · 특성 단계 · 특성 효과 수집) · `level.ts` (`1 + floor(√(총합 ÷ 10))`) |
| 4 | `core/stats.ts` | `deriveSlimeStats` 에 레벨 보너스와 특성 효과를 넣는다. **전투 엔진은 손대지 않는다** — 흡혈 · 피해감소 · 화상은 몬스터용으로 이미 구현돼 있고 슬라임도 같은 효과를 쓴다 |
| 5 | `session` | 진행이 바뀔 때마다 능력치를 다시 계산해 바뀌었으면 전투에 반영(지금은 강화 때만). 특성 단계 · 레벨 상승 이벤트 발행 |
| 6 | 저장 | `SCHEMA_VERSION` 2 + 첫 마이그레이션(v1 → v2, 흡수 0 으로 채움). v1 저장 샘플을 테스트 픽스처로 영구 보관 |
| 7 | `ui` · `game` | 흡수 시트 (계열별 막대 · 특성 단계 · 다음 문턱 · 진화 요건 진척), HUD 에 `Lv`, 하단 「흡수」 활성화, 로그 「박쥐 특성 2단계」. 기본 슬라임 색을 흡수 비율로 물들이기 · 처치 시 계열색 흡수 숫자 |
| 8 | 테스트 | 흡수 비감소 · 특성 문턱 · 레벨 공식 · 특성 효과 합산과 상한 · 전투 중 특성 반영 · 마이그레이션 · 데이터 검증 |
| 9 | 밸런스 | 시뮬레이터에 계열별 흡수 속도 추가. 「3 스테이지 클리어 + 한 계열 200」 도달 시각이 D12 첫 진화 목표(10~15분)에 맞는지 |

#### 5B — 진화 [M]

| 작업 | 내용 |
|---|---|
| 규칙 | `forms.json` · 형태 상태 계산 · `evolve` 커맨드 · 전환 비용 · 숙련 · 보스전 중 금지 (보스는 Phase 6 이라 검사만 미리) |
| 화면 | 진화 시트 (현재 ↔ 진화 후 비교, 확정) · 진화 알림 점 |
| 시각 | 형태 프리셋 3종 (흡혈 붉은 입자 · 철갑 금속 불꽃 · 화염 불길) |
| 연출 | 진화 연출 2초 (`pauseFor`) |
| 테스트 | 형태 상태 단방향 · 진화 검사 순서 · 전환 비용 |

**완료 기준**: 5A — 사냥한 계열에 따라 색과 특성이 달라진다. 5B — 세 형태로 각각 진화해 전투 모습과 숫자가 달라진다
**확인받을 것**: ★ **핵심 재미를 처음 체감하는 지점.** 여기서 방향이 맞는지 판단한다
