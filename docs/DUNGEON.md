## 1. 분석 — 왜 단조로웠나 (1차)

**구조.** 규칙은 `core/` 의 순수 함수, 화면은 이벤트를 그리기만 한다. 전투 엔진(`core/battle/engine.ts`)은 행동을 예정 시각 순서로 처리해
dt 를 어떻게 나눠도 결과가 같고, 같은 엔진이 오프라인 보상 · 시뮬레이터 · 테스트에 그대로 쓰인다. 진행은 커맨드(`applyCommand`)로만 바뀐다.

| 무엇 | 1차 전 상태 |
|---|---|
| 전투 | 슬라임 1 : 몬스터 1. 결과는 공격력 · HP 비교로 정해지고 플레이어가 끼어들 틈이 없다 |
| 선택 | 강화 순서 · 진화 형태 · 용병 편성 정도. 전투 방식이 바뀌는 선택은 없다 |
| 보스 | 강타 예고는 있지만 대응 수단이 없다 |
| 초반 | 자동 플레이 기준 1 스테이지 1분 → **2 스테이지 9분** → 5 스테이지 26분 |

## 2. 설계 원칙 — 기존 구조와 부딪히지 않게 얹는다

| 원칙 | 어떻게 |
|---|---|
| 기존 엔진은 그대로 | 사냥터 엔진은 필살기 게이지만 더했다. 쓰지 않으면 결과가 이전과 같아 오프라인 보상 · 기존 테스트가 그대로다 |
| 공통 로직 재사용 | 던전 엔진(`core/dungeon/engine.ts`)은 피해 공식 · 화상 · 흡혈 · 능력치 · 골드 · 흡수 · 용병 · 시드 난수 · 예정 시각 순서 모델을 그대로 쓴다 |
| 결과는 커맨드 하나 | 한 판이 끝나면 엔진 요약(`DungeonSummary`)을 `finishDungeon` 으로 반영한다 — 범위 · 단계 열림 · **판 id(같은 판은 한 번만)** 를 검사한다 |
| 계산과 그리기 분리 | `DungeonScene` 은 던전 이벤트와 읽기 전용 뷰만 본다. **세션 진행은 게임 루프(`createGame` 의 PRE_STEP) 한 곳** 에서 하고 장면의 update 는 그리기만 한다 |
| 저장 호환 | v7 → v8: 진행 중인 판(`dungeonRun`) · 반영한 판 기록(`dungeon.claimed`), 단계 번호를 스테이지 1 칸 기준으로 옮긴다. 서버(slimora-api)는 겉모양 · 스키마 번호만 보므로 변경 없음 |
| 의존성 | 추가 없음 |

## 4. 다수 몬스터 전투

- **대열** — 자리 5칸(`SLOTS`). 범위 폭발 · 연쇄 번개 · 불꽃 확산 · 독 번짐은 이 거리로 잰다. 보스는 맨 앞 자리
- **대상** — 기본은 맨 앞 적. 적을 누르면 그 적부터 친다(다시 누르면 해제). 발밑에 노란 고리. 누르는 영역은 최소 48px
- **개별 상태** — 몬스터마다 HP · 독 · 화상 · 기절 · 강타 주기, 보스는 패턴 · 경화 · 경직 · 격노
- **피해 판정** — 한 공격 안에서 직격 → 분열탄 → 폭발 → 번개 순. 폭발 · 번개 · 충격파도 치명타가 터진다
- **작은 수치** — 받는 피해 · 화상의 1 미만 나머지를 모아서 준다

## 5. 스킬 6종 — 공격 방식이 바뀐다

| 스킬 | 쓰임 (카드에 표시) | 1단계 → 3단계 |
|---|---|---|
| 화염 폭발 | 여러 적 · 범위 | 3번째 공격마다 주변 110% (중심 +50%) → 2번째마다 150% + 화상 |
| 연쇄 번개 | 여러 적 · 연쇄 | 2번째마다 3마리 90% → **매 공격** 4마리 85% + 20% 기절 |
| 분열 공격 | 여러 적 · 다발 | 분열탄 1개 60% → 3개 70% (적이 하나면 같은 적에게 절반 위력) |
| 독성 공격 | 보스 · 단단한 적 | 맞힐 때마다 1중첩(초당 11%) → 19% · 10중첩 · 쓰러지면 번짐. 피해감소 무시, 치명타 기대값만큼 세진다 |
| 보호막 | 생존 · 큰 공격 대비 | HP 50% 아래로 떨어지면 최대 HP 20% (22초) → 60% · 28% (15초) · 깨지면 충격파 |
| 광폭화 | 보스 · 처치 가속 | 처치마다 1중첩(최대 4, 중첩당 속도 +10% · 피해 +6%) → 6중첩 · HP 절반 이하면 늘 최대. 보스의 큰 공격을 맞으면 곧바로 최대 |

## 6. 시너지 5종

| 시너지 | 조합 | 효과 |
|---|---|---|
| 독화 폭발 | 화염 폭발 + 독성 | 폭발이 독 3중첩, 중독된 적은 폭발 피해 +50% |
| 폭풍 연쇄 | 연쇄 번개 + 광폭화 | 광폭 3중첩마다 번개가 1번 더, 최대 중첩이면 매 공격 번개 |
| 산탄 번개 | 분열 + 연쇄 번개 | 분열탄이 45% 로 작은 번개 |
| 화염 방패 | 보호막 + 화염 폭발 | 보호막이 깨지면 모든 적에게 화염 160% + 화상 |
| 독침 세례 | 분열 + 독성 | 분열탄의 독이 2중첩 |

처음 발견하면 보석 +20 과 함께 도감에 남는다.

## 9. 진화 형태 · 용병 연계

| 형태 | 던전 전투 방식 | 어울리는 스킬 | 세기 보정 |
|---|---|---|---|
| 흡혈 슬라임 | 피의 연쇄 — 처치하면 최대 HP 2% 회복, 다음 공격이 곧바로. 필살기 피해 15% 흡수 | 광폭화 | ×2.0 |
| 철갑 슬라임 | 가시 갑옷 — 받은 직격 피해의 20% 를 때린 적에게. 필살기가 보호막 20% | 보호막 | ×1.9 |
| 화염 슬라임 | 불꽃 확산 — 기본 공격이 주변에 40%, 화상 입은 적이 쓰러지면 옮겨 붙는다 | 화염 폭발 | ×1.0 |

**세기 보정**은 형태의 던전 전투 방식이 능력치 공식(초당 피해 × 실질 HP)보다 얼마나 센지를 시뮬레이션으로 맞춘 값이다 (15-6).
흡혈(여러 적을 칠 때마다 회복) · 철갑(피해감소가 최대 HP 비례 큰 공격까지 줄인다)은 같은 능력치의 화염보다 두 단계쯤 위를 깬다 — 그만큼 추천 단계가 높다.

| 연계 | 조건 (용병 외형 + 형태 또는 스킬) | 효과 |
|---|---|---|
| 박쥐 떼 | 박쥐 용병 + 흡혈 / 광폭화 | 용병 피해의 60% 만큼 회복 |
| 바위 방벽 | 골렘 용병 + 철갑 / 보호막 | 보호막 · 반격 ×1.5 |
| 불꽃 협공 | 드래곤 용병 + 화염 / 화염 폭발 | 용병 공격에 화상 |
| 젤리 분열 | 슬라임 용병 + 분열 공격 | 용병 공격도 3갈래 |

## 12. 2차 개선 — 무엇을 왜 바꿨나 (2026-11-04)

1차 구현 뒤 시뮬레이터를 확장해(15장) 재 보니 다음이 문제였다.

| 문제 (변경 전 측정) | 원인 | 고친 것 |
|---|---|---|
| 첫 던전: 규칙을 익힌 사람(무작위 스킬 · 예고를 보고 필살기) 40%, 모르는 사람 12% | 첫 판에 배울 기회가 없다 | 첫 클리어 전 1단계 도움 · 첫 내려찍기 가르침 · 버튼 신호 · 패배 분석 (14장) |
| 「적정」 단계가 없다 — 세기 0.7 이면 0~2%, 1.4 이면 97~100% | 단계 하나 = 스테이지 2 칸 → 세기가 단계마다 절반 | 단계 하나 = 스테이지 1 칸 (100 → 199 단계) |
| 공격 중심 조합 7~10%, 방어 25%, 분열 · 연쇄는 버리는 선택 | 범위 스킬이 혼자 남은 보스에게 약하고, 치명타 · 흡혈은 직격에만 | 폭발 중심 +50%, 스킬 치명타, 독은 치명타 기대값, 수치 조정 |
| 후반에 광폭화가 사실상 필수 (보유 89% · 미보유 36%) | 큰 공격을 맞으면 곧바로 최대 중첩 + 중첩당 큰 보너스 | 중첩당 속도 12 → 10% · 피해 8 → 6% |
| 흡혈 · 철갑 형태는 같은 능력치의 화염보다 2~4 단계 위를 깬다 | 흡혈은 여러 적을 칠 때마다, 철갑은 큰 공격까지 | 던전 흡혈 50%, 철갑 반격 50 → 20%, 흡혈 처치 회복 4 → 2%, 형태 세기 보정 |

## 15. 시뮬레이터 · 전략별 결과

### 15-1. 방법

- 자동 플레이어로 스테이지 S(2 · 6 · 12 · 24 · 40)를 막 깬 진행을 만든다 (가장 싼 강화부터 · 10 스테이지부터 화염 진화 · 보석이 모이면 용병)
- **전선 단계** = 세기 0.95 이상인 가장 높은 단계 (그 아래는 다 깼다고 본다). 스테이지 2 는 1단계 · 첫 판(도움 켜짐)
- 조건마다 **시드 200개, 공통 시드** (시드 i 의 던전 · 자동 플레이어 시드가 모든 조건에서 같다). 비율 옆 괄호는 95% 구간
- 시간은 ×1 전투 시간. 「분당」 값은 선택 1회 5초 + 시작 · 결과 6초를 더한 추정 시간으로 나눈다

| 전략 | 정의 |
|---|---|
| 스킬: 무작위 | 셋 중 아무거나 |
| 스킬: 시너지 | 새 시너지를 켜는 스킬 > 가진 스킬 올리기 > 형태와 어울림 > 시너지가 많은 스킬. 2 웨이브부터 노릴 게 없으면 다시 뽑기 (횟수 안에서) |
| 스킬: 방어 · 공격 | 우선순위 — 보호막 · 연쇄 · 독 · 광폭 · 분열 · 폭발 / 폭발 · 분열 · 연쇄 · 광폭 · 독 · 보호막 |
| 스킬: 단일 집중 | 그 스킬이 나오면 그것, 아니면 다시 뽑기 · 가진 스킬 |
| 필살기: 무작위 | 다 차고 0~8초 뒤 아무 때나 (예고를 보지 않는 사람) |
| 필살기: 즉시 · 안씀 | 차는 대로 / 쓰지 않음 |
| 필살기: 적절 | 보스가 있으면 큰 공격 예고 · 경화에 0.3~1.1초 뒤 반응, 10% 는 놓친다. 일반 웨이브는 적이 셋 이상이거나 HP 35% 아래 (규칙을 익힌 사람) |
| 필살기: 완벽 | 적절과 같은데 즉시 반응 · 놓치지 않음 |

모든 전략은 엔진이 제시한 셋 중에서만 고르고 다시 뽑기 횟수를 넘지 못한다 (넘으면 `runDungeon` 이 던진다 — 회귀 테스트).

| 백그라운드 | 화면이 가려지면 그 순간을 저장하고 멈춘다. 돌아오면 「일시정지 — 멈춰 둔 곳에서 이어집니다」. 그대로 꺼져도 같은 순간부터 — 「질 것 같으면 끄고 다시」가 통하지 않는다 |
| 손상 | 하나라도 어긋나면(모르는 몬스터 · 보스 · 스킬, 단계 · 웨이브 불일치, 간격 0, NaN, 자리 겹침 …) 그 판만 버리고 알린다. 진행 상태는 그대로 읽는다. 무작위로 값을 망가뜨린 400가지에서 던지지 않고, 받아들인 판은 끝까지 돌아간다 (테스트) |
| 엔진 정지 | 그래도 엔진이 행동 수 상한에 걸리면 그 판을 그때까지의 보상으로 끝내고 게임은 계속된다 |
| 설정이 바뀌면 | 보스 패턴 수치는 지금 설정에서 다시 잇고, 순서가 어긋났으면 그 예고만 접는다 |
| 크기 | 가장 큰 저장(결제 기록 100 · 반영 기록 20 · 보스전 한가운데) 16KB 미만 (서버 한도 32KB) — 테스트. 실제 저장은 약 3KB |

### 16-2. 중복 보상 방지

| 경우 | 막는 것 |
|---|---|
| 결과 화면 재진입 · 버튼 연타 | 보상은 판이 끝나는 순간 한 번 반영된다. 포기 · 나가기 · 다시 도전을 여러 번 눌러도 한 번 (테스트) |
| 앱 종료 후 복귀 | 보상 반영과 체크포인트 삭제가 같은 저장 — 둘 중 하나만 남는 상태가 없다 (테스트) |
| 같은 판을 두 번 끝냄 | 판 id(`runId`, UUID)를 `dungeon.claimed` 에 기록(최근 20판). 같은 id 는 `ALREADY_CLAIMED` — 결과만 보여 주고 보상 없음 (테스트) |
| 서버 동기화 충돌 | 다른 기기의 진행으로 바꾸면(adopt) 이 기기의 판은 버린다 — 받아 온 진행에 보상이 한 번 더 들어가지 않게. 받아 온 저장에 판이 있으면 그 판을 이어할지 묻는다 (테스트) |
| 엇갈린 저장 (B 의 진행 + A 의 체크포인트) | 그 판의 id 가 이미 반영돼 있으면 보상 없이 결과만 (테스트) |
| 실패 보상 반복 | 실패도 판 하나 = 반영 한 번. 4 웨이브 포기 반복은 결정 2.1~2.6/분으로 클리어(4.3~5.2/분)의 절반 |

### 16-3. 클라이언트 데이터는 믿을 수 없다 — 서버 검증이 필요한 위험

저장 체크섬(FNV-1a)은 **손상 감지용이지 조작 방지가 아니다.** 저장을 직접 고치면 골드 · 보석 · 결정을 마음대로 만들 수 있고, 지금 서버(slimora-api)는 봉투의 겉모양 · 크기 · 스키마 번호만 본다.
이번 작업은 서버를 바꾸지 않았다. 필요해지면 할 일:

| 위험 | 악용 | 대응 방안 (서버 변경 전 검토) |
|---|---|---|
| 저장 조작 | 로컬 저장의 gems · purchases 를 고쳐 서버에 올린다 → 다른 기기 · 재설치에도 남는다 | 서버가 직전 사본과 비교해 재화 증가 폭을 상한으로 막기 (시간 · 진행 대비) |
| 던전 결과 위조 | `dungeonRun.rewards` · `best` · `cleared` 조작 → 첫 클리어 보석 | `finishDungeon` 요약 + 시드 + 선택 · 필살기 입력 기록을 서버가 같은 엔진으로 다시 돌려 확인 (엔진이 결정적이라 가능) |
| 결제 재화 | 주문 기록(`orders`)은 클라이언트 것 | 결제는 스토어 영수증을 서버가 검증해 지급 (지금은 앱이 지급) |

## 18. 모바일 화면 · 성능 점검 (개발 환경에서 본 범위)

**해상도.** 360×640 · 375×667 · 375×812 · 412×915 · 430×932 · 768×1024 에서 보스전(시너지 4개)과 스킬 선택 화면의 겹침을 재 봤다 — HUD · 보스 막대 · 팁 · 스킬 막대 · 토스 버튼 자리(오른쪽 위 104px) 사이 겹침 0, 가로 넘침 0, 스킬 선택 창 세로 넘침 0, 11.5px 미만 글자 0.

| 고친 것 | 전 → 후 |
|---|---|
| 일시정지 · 포기 확인 창 | HUD 안에 그려져 HUD 높이만 가리고, 어두운 부분을 눌러도 전장으로 통과했다 → 앱 전체 겹창 (포기 확인도 같은 문제였다) |
| 안내 한 줄(토스트) | 보스 막대 · 「필살기로 끊기!」를 덮었다 → 스킬 막대 바로 위 빈 땅 |
| 몬스터 터치 영역 | 박쥐 39px 높이 → 최소 48px (그림 둘레로 넓힘) |
| 시너지 칩 | 360px 에서 두 줄이 되어 전장을 밀었다 → 셋까지 + 「+N」 한 줄 |
| 보스 · 부하 겹침 | 큰 보스 몸에 부하가 겹쳤다 → 보스가 있으면 부하를 오른쪽으로 비켜 세운다 |
| 웨이브 배너 | 짧은 화면에서 보스 막대 뒤로 숨었다 → 화면 높이 34% → 40% |
| 피해 숫자 | 체력바 위에서 시작 (막대를 덮지 않게) |
| 포기 확인 중 | 전투가 계속 흘렀다 → 묻는 동안 멈춘다 |
| 이어하기 직후 | 사냥터 장면이 불러오는 중이면 두 장면이 함께 돌아 두 배 속도 → 진행은 게임 루프 한 곳, 사냥터는 스스로 잔다. 120 프레임에 정확히 2,004ms 진행 확인 |

**정리.** 던전 → 포기 → 사냥터를 6번 오가도 던전 장면 오브젝트 58개 · 세션 구독 6 · 던전 구독 2 로 늘지 않는다. 사냥터 장면은 39 에서 멈춘다(피해 숫자 풀).
**숨겨진 화면.** 화면이 가려지면 rAF 가 멈춰 게임 시간도 멈추고, 돌아온 첫 프레임은 250ms 까지만 따라잡는다. 던전은 「일시정지」로 연다.

**확인하지 못한 것.** 실기기 프레임 · 발열 · 메모리(중급 안드로이드 WebView), 실제 손가락 터치 감, 실시간 애니메이션 속도(확인 환경은 화면이 숨겨져 프레임을 손으로 돌렸다), 효과음 · 진동.
